# Портфолио - Nursultan Bergaliev

Статический сайт-портфолио: главная плюс 5 отдельных страниц кейсов, тёмная тема, переключение EN/RU.

## Структура

```
index.html                 главная: hero, кейсы, опыт, навыки, контакты
work/invitro.html          кейс: медицинская регистратура (Invitro)
work/avito.html            кейс: планировщик интервью (Avito)
work/wink.html             кейс: CMS стримингового сервиса (Wink / Ростелеком)
work/siemens.html          кейс: CMS планирования мощностей (Siemens)
work/umi.html              кейс: сайты и магазины на UMI.CMS
assets/style.css           вся стилизация
assets/site.js             переключатель языка (~40 строк)
Nursultan_Bergaliev_CV.pdf резюме, скачивается кнопкой с главной
.nojekyll                  чтобы GitHub Pages не прогонял файлы через Jekyll
src/                       генератор страниц (нужен только для правок контента)
```

## Публикация на GitHub Pages

### Вариант A - персональный сайт, адрес `https://anysound.github.io/`

Создай публичный репозиторий с именем **`anysound.github.io`** и залей туда содержимое этой папки:

```bash
cd путь/к/этой/папке
git init
git add .
git commit -m "Portfolio site"
git branch -M main
git remote add origin https://github.com/anysound/anysound.github.io.git
git push -u origin main
```

Дальше в репозитории: **Settings → Pages → Build and deployment → Source: Deploy from a branch**,
ветка `main`, папка `/ (root)`. Через минуту-две сайт откроется по адресу `https://anysound.github.io/`.

### Вариант B - проектный репозиторий, адрес `https://anysound.github.io/portfolio/`

То же самое, но репозиторий называется, например, `portfolio`. Все ссылки внутри сайта относительные,
поэтому он одинаково работает и в корне домена, и в подпапке - менять ничего не нужно.

### Свой домен

Если появится домен: **Settings → Pages → Custom domain**, вписать его, и в этой папке создать файл
`CNAME` с одной строкой - именем домена.

## Как править контент

Весь текст лежит в одном месте: `src/data.js`. Там профиль, кейсы, таймлайн и навыки, каждый текст
парой `{ en, ru }`. После правки:

```bash
cd src
node build.js
```

Скрипт перезапишет `index.html` и все страницы в `work/`. Node нужен только для этого шага -
на GitHub Pages ничего не собирается.

Хочешь добавить кейс: скопируй любой объект в массиве `cases` в `src/data.js`, поменяй `slug`
(он же имя файла) и содержимое, запусти `node build.js`. Страница и карточка на главной появятся сами,
навигация «предыдущий / следующий» между кейсами тоже пересоберётся.

## Как это устроено

**Переключение языка.** Оба языка лежат в HTML одновременно, каждый в своём элементе с атрибутом
`data-lang`. CSS прячет неактивный:

```css
html[lang="en"] [data-lang="ru"],
html[lang="ru"] [data-lang="en"] { display: none !important; }
```

`assets/site.js` только меняет `lang` у `<html>` и запоминает выбор в `localStorage` (в приватном
режиме молча работает без запоминания). Первый визит: если язык браузера русский - открывается RU,
иначе EN. Плюс подхода в том, что оба языка есть в разметке для поисковиков, и сайт не ломается,
если JS не выполнился.

**Шрифты** подключены с Google Fonts (Inter и JetBrains Mono) с системным фолбэком - если шрифты
не загрузились, вёрстка не рассыпается.

**Доступность.** Есть skip-link, видимый фокус, контрастность текста к фону выше 4.5:1,
`prefers-reduced-motion` отключает анимации.

## Что стоит доделать позже

- Скриншоты или короткие видео интерфейсов в кейсы. Сейчас страницы текстовые, а фронтендера
  оценивают глазами. Если по NDA нельзя показывать реальные экраны - подойдут схемы архитектуры
  или обезличенные наброски.
- Ссылки на живой код в кейсах, где это возможно.
- `og:image` для красивых превью при отправке ссылки в мессенджер.
